# Remove the DeepL translate engine

DeepL's free tier is capped at **1 million characters, lifetime** — not per month, ever. In real use that budget runs out quickly, and once it is gone the key is dead permanently: every request fails with a quota error that no retry or setting change can fix. An engine whose free tier cannot actually serve the app's continuous screen-translation workload is a dead-end option that steers users into a wall, so we decided to remove the DeepL Translate Engine from the app entirely — the engine registry, the engine implementation, the config template and its validation, the settings surface, and the docs. Users whose saved config still names DeepL (as the default engine, as the rate-limit fallback, or as a Profile's engine) are migrated once at config load, before validation: the default engine falls back to Google (ADR-0002), the fallback resets to "none", and Profile engines revert to inheriting the global engine. The config file is rewritten only when a DeepL reference was actually found, and the same launch announces the changes once through the established channels (Results Window banner + app log) — because the file is rewritten clean, the notice genuinely fires exactly once, with no persistent "shown" flag. An old `[engines.deepl]` settings section left by a hand-edit needs no migration: serde ignores the unknown table and the next save drops it. Translation Cache entries produced by DeepL simply become unreachable and age out through the existing LRU.

## Consequences

- The removed name is simply unknown: a "deepl" that somehow reaches validation (the settings-save path validates without migrating) surfaces as the registry's unknown-engine error listing the five live engines — never a silent fallback and never a "broken config".
- The load-time chain is parse → migrate → validate; the save-time chain stays parse → validate. That asymmetry is the design: old files heal on load, new choices are rejected where the user is looking.
- Do not re-add DeepL (or any engine whose free tier is a lifetime cap) without replacing the unusable-free-tier story itself — a keyed engine only earns its slot if its free tier can survive real screen-translation volume, as Azure's F0 (2M chars/month) can.
