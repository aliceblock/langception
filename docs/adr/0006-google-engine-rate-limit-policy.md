# Rate-limit policy for the free Google engine

_Amended (2026-11, no new ADR — the consequences below pre-authorize leg changes): the two-leg chain recorded below — gtx, then the Chrome Dictionary extension — gained a keyless Chrome-Translate-extension leg (clients5.google.com/translate_a/t) as the second leg, demoting the dictionary extension to third; it is keyless, answers an honest User-Agent, and draws from a separate, quieter quota pool. The chain decision, the cool-down policy, and the error contract stand._

The default engine (ADR-0002) is the free unofficial Google endpoint, which throttles per IP (HTTP 429) under real screen-translation volume; a comparable product (the FFXIV plugin Echoglossian) survives on the same free access through a different quota pool and aggressive caching. We decided the Google engine gains three composed mechanisms instead of switching the default to a keyed engine: an internal endpoint chain — the gtx JSON endpoint, then the Chrome Dictionary extension endpoint; a planned third mobile-web leg was cut before it shipped, because scraping the answer out of an HTML page without an HTML parser is more fragility than two legs already buy — where a rate-limited endpoint cools down (60 s doubling to a 10-minute cap across consecutive strikes; a served request resets the ladder, since it proves the leg healthy again) and the chain serves the request from the next leg without stalling the sequential loop; the loop's existing failure contract stands unchanged — a text that fails during a cool-down retries only when its pixels change again, never proactively; and an opt-in setting routes requests to a user-configured secondary Translate Engine while every Google leg is cooling down, each switch announced through the same channels as engine errors, off by default because a mid-session engine change alters translation style. Alongside, a persistent Translation Cache (per text, language pair, and producing engine; clearable in Settings) cuts repeated requests for every classic-mode engine.

## Consequences

- The dictionary-extension leg impersonates Google's own client one step beyond gtx: its key is public and Google rotates or retires it periodically. The chrome-ex leg is keyless and answers an honest User-Agent, but it is still an unofficial client of Google's translate surface and can change without notice. A burned key or a moved endpoint degrades the chain gracefully — that leg cools down and the error contract holds — but expect to re-order, relocate, or retire legs over the app's life.
- No in-pass sleep: the loop is sequential, so rate-limit recovery happens across passes, never by stalling a pass.
- A failed leg surfaces as a normal engine error only when every leg is cooling down; otherwise the request succeeds from a later leg and the user sees nothing.
- The opt-in auto-switch stores cache entries under the engine that actually produced the translation, so a fallback translation is never served later as a Google one.
- ADR-0002's visibility contract is unchanged and extended: fallback switches announce like engine errors (tray + Results Window), never silently.
